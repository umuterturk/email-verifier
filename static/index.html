What this validates

VALID means the address is syntactically OK and the domain can receive mail. It does not mean a specific inbox exists.

We check

  • Syntax
  • DNS and MX records (the provider can accept mail)
  • Known disposable domains
  • Role addresses (info@, admin@, and similar)
  • Alias normalization for major providers
  • Typo suggestions
  • A derived score and status

We don't check

  • SMTP RCPT TO
  • Whether a specific mailbox or inbox exists
  • Catch-all domains
  • Whether a message will bounce

mailbox_exists is true when the email provider (domain MX) can accept mail. It matches mx_records and does not prove the local-part mailbox exists.

Why we don't check SMTP

SMTP RCPT TO asks a mail server if it will accept one address. That reply does not prove the mailbox exists. Major providers hide whether the inbox is real, catch-all domains accept every address, and many servers block or throttle automated checks. It is also too slow: each address needs its own live connection to a mail server. A yes would look like inbox verification and still be wrong, so this API never sends one.

Why we can't know if an email exists

No check can say with certainty that a specific mailbox exists. Syntax only says the address is well formed. DNS and MX only say the domain can accept mail, not that this local-part is real. There is no public directory of inboxes. Even SMTP cannot settle it, because providers hide existence and catch-all domains accept every address. An address can pass every check here and still not be a real inbox. The reliable confirmation is double opt-in: the person clicks a link you send.
